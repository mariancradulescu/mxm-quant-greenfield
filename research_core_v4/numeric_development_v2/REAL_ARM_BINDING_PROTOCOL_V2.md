# Exact DEVELOPMENT ARM binding V2

Operational successor only. The original scientific design, kernel, reducer,
accepted100shard corpus and all historical authorities remain byte identical.

1. Publish an immutable source commit S containing implementation and the source
   SHA256 manifest. No ARM or approval is needed to calculate S.
2. Publish a canonical candidate ARM in later commit A. It names S, the exact
   bound source hashes, accepted manifest, design/kernel/key fingerprint,
   full1576 frontier, three lags, four weeks and finite resource limits.
3. An independent auditor must inspect S/A and the machine evidence, obtain the
   user's explicit acceptance, then publish a separate approval artifact in
   commit P. P may change only INDEPENDENT_ACCEPTANCE_V2.json. Approval names A,
   S and the exact candidate ARM SHA256, never P's own SHA.
4. Execution commit H must descend from S/A/P. Every bound local file must match
   both S and its exact SHA256. Approval has an independent-auditor role and an
   audit-receipt hash; no real acceptance is generated by the executor.
5. Dispatch additionally supplies S and the accepted ARM digest outside Git.
   Missing, wrong, stale, wider or consumed authorization denies execution.

This is procedural audit separation with enforced separate Git artifacts.
It does not certify an unseen auditor's identity cryptographically. Repository
write access alone is not independent scientific acceptance. The auditor/user
must actually accept the exact bytes; a role string is not proof of independence.

The stable original claim is keyed by experiment+design+accepted dataset, not by
a mutable code HEAD. Atomic Git ref creation admits one original invocation and
denies all subsequent originals, including changed-code duplicates. Automatic
workflow reruns are denied. A failed consumed invocation remains consumed.

A recovery is a separately accepted single continuation of the same invocation.
It binds original run, ARM and approval digest, exact remote checkpoint receipt
ciphertext digest and next ordinal. A separate atomic recovery ref denies races
and duplicate use. Its previous-resource ceiling must include the entire first
attempt (including work lost after the checkpoint), independently checked from
run/job evidence. Cumulative CPU/wall limits apply across the continuation.

The encrypted checkpoint contains all1576 causal buffers, clock counters,
per-lag and four-week accumulators, clock vectors, cross-lag state, source-prefix
identities and hashes. Cold recovery fetches remote receipt and ciphertext,
validates byte/hash/canonical bindings, and starts at next_shard; it cannot take
local engine state as input. No completed durable shard is replayed.

Default real-mode state is denied until a separate exact independent approval.
This task creates a candidate only. No real market responses are authorized.
