# Native cTrader CLI artifact metadata reception, isolated from accounts and networking

Baseline: canonical `0705fe26f1dc1c6e9acab1bde734c8affff3cadf` (PR169–170). Preserve all existing product safeguards, checkpoints, scientific partitions and economic closures. This is a native package/parameter reception step; no economic experiment, new market source or trading run.

## Concrete gap and change

The canonical product targets .NET6 with pinned `cTrader.Automate1.0.21`. An attempted .NET8 migration compiled the DLL but failed actual SDK packaging in required CI with `CT0004: Target framework "net8.0" is not supported`. This failed attempt is preserved in PR171 source26b207b4e7ed7454609ec8df3f8c483ebf32b05e and run40107650780/job120912567328 (also other required compiler checks). No failed check was waived or SDK guard bypassed. The project and existing package assertions were restored exactly to canonical net6; no .NET8 product migration or operational compatibility is claimed.

Current generic CLI instructions require .NET8 cBots, while the available pinned SDK rejects that packaging target. This conflict is retained explicitly. The bounded question here is whether the actual vendor CLI can read the metadata of the ORIGINAL canonical SDK-produced package. Positive metadata reception would establish only that package/parameter read, not override the documented runtime requirement or certify cBot start. Strategy/safety sources, source set, SDK and project are unchanged.

Official CLI references distinguish the no-auth batch form `metadata <path>` from the authenticated interactive route. Their generic authentication table is less specific and lists metadata alongside authenticated commands; this task verifies actual behavior rather than infer that credentials are necessary. Do not supply `-q`, auth flags or cTID/OpenAPI values. The existing OpenAPI credentials are neither used nor substituted for cTID credentials.

## Pinned vendor and isolation contract

Use the official Linux x64 archive `https://getctrader.spotware.com/cli/homebrew/ctrader-cli-5.9.0-linux-x64.tar.gz`, pinned to103434349bytes and SHA256 `da0f5fb0c58980be9143fafca9839de784084b6e323321d9e03e5c3e64bec562`, from Spotware Homebrew formula commit `42a7eacb26a4c28b84df39ca7e5689e4b909fa2c`. The archive has637 members /334700988 declared expanded bytes, locally inspected before execution. Extraction uses the Python data filter and explicit bounds, then restores executable bits as the vendor formula requires. No alternate provider, mutable latest image or silent binary upgrade. A local socket/connect/send-denied version-only call returned `5.9.0.28`; this is a preliminary tool check, not product reception.

The existing no-secret account CI builds the actual canonical .algo and checks the emitted product assembly carries its original .NET6 framework marker. It then runs only three vendor commands: `--version`, `metadata <actual-product.algo>`, and `metadata <deliberately-malformed.algo>`. No `run`, `backtest`, account, price, history, order or Cloud command exists in this allowlist. Source defaults remain DEMO disabled and empty portfolio roster. The native Robot's real-time persistence gate still rejects CLI/Cloud execution; metadata reading must not be confused with permission to start it.

Each command is launched inside a NEW Linux network namespace, then under the original non-root runner UID, with all bounding/effective capabilities removed and no-new-privileges enabled. Before vendor execution the worker verifies its namespace differs from the parent, no external IPv4 route exists, and the only environment keys are HOME/PATH/LANG. HOME is a fresh temporary directory; network sockets are not inherited through standard streams. No custody key, GitHub token or broker/cTID credential is passed. Network namespace isolation blocks both IPv4/IPv6 access to the host/broker; an empty IPv4 route table is an additional check, not the sole isolation measure. This protects against unintended connectivity, not a hostile kernel/vendor supply-chain threat model.

Native stdout/stderr and exit codes are bounded and preserved. Positive reception requires actual-product metadata return0 and all12 distinct source parameter identities; a help banner, incomplete set or suffix-only match cannot pass. The deliberately malformed package must return nonzero. The actual native process output is retained; it is not fabricated from reflection, a C# shim or source parsing. Parameter identity recognition does not by itself certify every default value or runtime behavior.

## Evidence and limits

A successful receipt must bind source SHA, actual vendor version/tar hash, original .algo and assembly digests, metadata stdout digest, all12 recognized parameter identities, malformed-package rejection and observed per-command namespace/privilege/environment state. Preserve the original compiled product, original native output and receipt as a CI artifact. Any native command or contract failure fails the required check; availability/parser errors are not product acceptance and must not be waived as SUCCESS.

This establishes only **NATIVE_VENDOR_CLI_PACKAGE_METADATA_RECEPTION** if the required run actually passes. It does not establish cBot start, broker callbacks, request/stop execution, LocalStorage crash durability, CLI/Desktop operational parity, recovery of unknown orders, after-cost competitiveness, EUR200 feasibility or HARD21. No authentication or account-side behavior is inferred from successful metadata. The complete native operational acceptance remains open.

Product project, strategy/safety sources and guards are unchanged. Existing native before-call checkpoint semantics remain: pending/unknown markers block startup, unsuccessful calls cannot disarm them, and missing storage cannot be distinguished from first installation without a separate anchor. All economic rejections remain closed without parameter/roster rescue. No new research trial, market request, broker order, Cloud activation, external research provider, custody/authority/checkpoint/C033/V2 mutation or user-operated procedure is introduced.
