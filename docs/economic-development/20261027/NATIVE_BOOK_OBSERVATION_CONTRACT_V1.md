# Native observation state contract — 27 October 2026

This is new descriptive C# product infrastructure, not a reinterpretation of the original source profiles. The same `MxmBookObservation<T>` state machine has typed factories for exact decimal raw fields and native double callback snapshots, using the existing shared geometry classifier. No strategy, fill, account, capital, fee or historical source policy is replaced.

Each local epoch starts without carried prices or clocks. A received event, explicit side observation and actual value change have distinct monotonic clocks. The first side value initializes the book; it does not demonstrate a change. Repeating a side value updates observation, not change time. An empty partial message updates event time only. Native `Symbol.Tick` supplies a callback snapshot of both sides; its sides are not relabeled as an OpenAPI wire-field mask. The callback records the local host receipt UTC and monotonic clock; its source timestamp remains absent. A sampled broker clock is not invented as a source event timestamp.

Silence increases reported ages while retaining descriptive geometry; it neither fabricates fresh observations nor proves unavailable liquidity. Last carried geometry, callback activity and transport reports always leave `ExecutabilityProven=false` and `ContinuousObservationProven=false`. Host UTC/source stamp may differ or reverse; they are retained descriptively and never substituted for monotonic elapsed time. The observer does not certify their accuracy or synchronization. Negative/regressing local monotonic clocks latch a fault with cleared book; a new epoch cannot clear that fault in the same instance.

A reported transport DOWN ends the epoch and clears all price clocks. A subsequent UP cannot resurrect the old book; a new epoch must initialize it again. Epoch start itself resets transport evidence to UNKNOWN. The native Robot does not claim transport status from ticks and does not invoke the transport-report API: its epoch is a **local subscription lifetime**, not proof of a continuous broker connection. A full Robot restart starts cold observation state; existing durable entry/fill/recovery ledgers remain authoritative. These transient source clocks cannot authorize an order, reset capital, count a HARD21 entry or recover an unresolved broker operation.

The actual product constructs one observer per configured symbol, feeds callback snapshots before the unchanged geometry/intent path and reports only counters on stop. Faults use the existing callback safe-stop path. Stop cleanup catches an observer fault so it cannot prevent other local observer cleanup. No new timer, polling, reconnection, broker request, capture or launch is introduced. Locked geometry remains handled by the old native predicate; this does not imply free trading.

Validation uses an independent Python state oracle against the compiled component: partial/unchanged/empty messages; long silence; native snapshots; explicit local epoch and transport boundaries; clock failures; wall/source reversals; exact raw integers beyond double precision; and 1,000 deterministic randomized actions for each origin. The real cTrader project explicitly compiles the same source. Required gateway CI must execute all compiled tests; missing .NET is a CI failure. Local .NET is absent, so local structural checks do not constitute compiled reception. Native Robot callbacks/orders are not executed by CI and remain unqualified.

## Economic admission decision

Existing strict five-second positive-spread source outcomes, diagnostic exclusions and closed economic identities remain unchanged. The observer is not permission to rescore those samples. Future exposure research must register the mechanism and response contract before directional data access, identify raw-field versus callback origin, and declare what remains unresolved between observations. Neither the last change nor the last message alone can certify a continuously executable exposure path. Dated commission, margin and cost/loss-side FX evidence must separately match the instrument, volume, account asset and study interval; no September terms may be inferred from October snapshots.

The next finite source reuse should evaluate the **already captured contemporary minimum-volume margin/contract evidence**, without another stream or model. It must distinguish a necessary EUR200 margin/fee bound from actual feasible order execution, stop risk and historical applicability. This is a different question from the already completed 1,140-event causes and broad October commission-only frontier; do not repeat either census. A later economic candidate still needs a separately frozen prospective protocol and independent confirmation.

Authorities, custody, single continuous EUR200, HARD21, existing controls and the prohibition on unauthorized LIVE/DEMO orders/Cloud are unchanged. B–E remains OPEN; no economic edge or operational Robot reception is claimed.
