# Tranziția după recepția laboratorului

Prioritatea finalizării laboratorului este separată de descoperirea unui edge. Campania extinsă nu este un test de infrastructură și nu este lansată prin simpla publicare a acestui document.

Directorul poate folosi aceeași sursă/workflow pentru programe noi în `research_programs/admissions/`, fără un nou mandat OWNER. Programul trebuie să declare întrebarea și distincția față de istoricul consumat, informația așteptată, dependențele originale, populația DEVELOPMENT, bugetele/identitățile, costurile sau certificatele de bound, criteriile de continuare/oprire și protecția confirmării. Extensiile de operator necesită o sursă nouă versionată, fără reactivarea programelor închise.

Ordinea de pregătire: inventar/cache autentic → hartă minimă a dependențelor necesare întrebării selectate → achiziție read-only numai pentru lipsurile rezolvabile legitim → screening nativ cu costuri conservatoare → aprofundare doar pentru candidați justificați → robustețe și validare separată. Prioritățile se aleg după informație și potențial economic, nu după un număr de simboluri sau variante de parametru.

Bugetul V2 conservat este 84, utilizat21, rămas63, fără refunduri; cele16 încercări legacy și selecția dependentă V3/V4 rămân parte din context. Un nou model/allocator/exit material nu poate fi strecurat sub o identitate veche.

Incertitudinile istorice irecuperabile ale rezultatelor V4–V6 sunt păstrate ca atare; nu se repornește pilotul și nu se fabrică continuitate. Datele lipsă nu sunt demonstrații de neprofitabilitate. Selecția următoarei întrebări trebuie să evite un nou ciclu fără sfârșit de diagnostic al aceleiași lacune.

Nicio țintă de randament ori risc arbitrară nu este adăugată. EUR200 rămâne o singură înzestrare inițială pe un cont continuu. Datele protejate, ordinele reale și START-ul competiției rămân închise. CBot-ul nu este promovat pe rezultate sintetice ori pe simpla compilare.
