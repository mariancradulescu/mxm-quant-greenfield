# Native order-free reception route in the existing Robot

Continuation after PR #241, official87d822c563ca2436e82d729c83cd8b3cc63166b4. The exact quote-innovation originals are integrated and its NET_FAIL_SCENARIO remains closed. No market research, source recapture, encrypted-result republication or economic retuning accompanies this change.

The previous blanket non-Desktop stop also prevented order-free Cloud callback reception. The **same** MxmReferenceProductBot now has explicit `Native Observation Only`, defaultfalse. With that option true, EnableDEMOTrading must befalse and the run must not be a backtest/optimization simulation. Recognized native environments are Desktop/CLI/Cloud; an unknown environment stops. The observation path branches before roster/strategy/kernel, persistence, original pending-intent recovery or confirmed-entry ledger initialization. Ordinary operation retains the non-Desktop persistence guard and ALL existing trading/risk/storage/ownership checks.

A shared MxmNativeRunFence binds the purpose once. Its default/uninitialized state denies account mutation; an observation purpose stays latched after parameter changes, exceptions and stop. Rebinding cannot escalate: it stops permanently. ExistingPath is only permission to enter the original guarded path, never permission to place orders. ApplyPortfolioDecision, both portfolio callbacks, broker-close callback, timer, defensive close and protection-halt action refuse observation/stopped/uninitialized mode. The existing pending/confirmed-ledger read/write delegates additionally reject before touching LocalStorage. A stopped instance cannot reopen itself.

The observation startup resolves only the existing chart symbol and timeframe, reuses MxmBookObservations.NativeSnapshots, and subscribes to the existing native Symbol.Tick/Bars.BarClosed APIs. It does not request a broad universe, call order methods, create a trading strategy or timer, poll/re-subscribe to manufacture quote freshness, or use HTTP/WebSocket/files/LocalStorage. Existing MxmBrokerOpeningInventory supplies one bounded read of available positive deal facts at startup; errors remain UNAVAILABLE, with no empty-history/retry/intent-clear inference. No account balance, order label/comment, raw account number or market price is printed by the observation reporting. The run uses an ephemeral observation ID and SHA256 account-scope fingerprint; neither is an original trade intent or durable account-genesis anchor.

READY only means subscriptions were installed. FIRST_TICK is emitted only after an actual callback, then BAR_CALLBACK summaries and a STOP summary. The common view reports local monotonic/receipt clocks, callback/change counters and descriptive geometry; original wire-side timestamps stay absent and transport staysUnknown. Closed-bar callback/repeat counts are descriptive; a late weekend bar is not promoted to a fresh signal. No total-history/continuous-observation/executability/native-trading/restart-recovery/capital/HARD21 qualification follows from these summaries. Native snapshots are not raw OpenAPI field masks. Restart creates a NEW observation run, not continuity of a lost trading session.

Stop first latches denial, then unsubscribes only the read-only callbacks and reports bounded in-memory state. Observation exceptions stop without invoking trading recovery, defensive close or ledger writes. An existing owned/foreign broker position is never modified or adopted by this mode. The purpose latch is used instead of reading a mutable parameter in later callbacks.

**This implements a route needed for future legitimate native reception; it is not that reception.** No Cloud instance, Desktop, CLI login or broker order is started in this continuation. Native callback availability with the installed .algo, actual platform/account identity, exception behavior and restart logs remain unreceived.
